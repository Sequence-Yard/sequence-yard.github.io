DBR-1

MIDI クロックの正確さ — しくみ・測った結果・同期のしかた

DBR-1 を MIDI クロックのマスター（CLOCK: SEND）にして、ほかの機材を動かす人向けのページです。Android の上で DBR-1 がクロックをどう送っているか、何を測ったか、どのつなぎ方と設定がいちばん安定するかをまとめました。設定の項目そのものは取扱説明書の MIDI の章にあります。

1. まとめ

  • DBR-1 はクロックの時刻を正確に決めています。1 つ 1 つのクロックに付ける時刻の誤差は、どのテンポでも最大で音声の 1 サンプル（約 0.02ms）です。
  • ふだんのクロックは、専用機と同じくらい安定しています。PC で測ると、ふだんのずれは、同じ方法で測った専用のグルーヴボックスと同じでした（中央値 約 0.2ms）。
  • 違いは「ときどき遅れるクロック」です。試したタブレットでは、50 個に 1 個ほどが 1ms 以上遅れて届きました（専用機は 500 個に 1 個ほど）。その大半は、DBR-1 が渡した後の Android の中で起きていて、アプリからは減らせません。
  • 聴いてわかるリズムのずれは、ほぼありません。平均のテンポはずれていきません。PC から USB で送るクロックや、機材どうしのクロックにも、1ms 前後の揺れはふつうにあります。

2. DBR-1 のクロックの送り方

時刻は音声エンジンが決める

MIDI クロックはテンポの数字を運びません。受ける機器が、クロック（4 分音符に 24 個）の間隔から自分でテンポを求めます。なので、1 つ 1 つのクロックが時刻どおりに出ることが大事です。

  • DBR-1 のシーケンサーは音声の処理の中で動き、サンプル単位で数えています。クロックもそこで数え、8 分音符ごとに合わせ直します。スウィングで遅らせるのは裏のステップだけなので、クロックは揺れません。
  • メッセージには「届ける時刻」を付けます。DBR-1 自身の音が実際に聞こえる時刻です。外の機材と DBR-1 の音が一緒に鳴るようにするためです（必要なら MIDI… の OFFSET で手で前後できます）。
  • 音声の処理が呼ばれる時刻そのものは、数 ms 揺れます。DBR-1 はこの揺れを MIDI に乗せません。時刻の基準は鳴らしたサンプル数で進め、本当の時計にはごくゆっくりだけ寄せます。

画面の処理に止められない送り方

  • 送るのは Java の外で動くネイティブのスレッドなので、画面の処理やメモリの片付け（GC）に止められません（SENDER: NEW、Android 10 以上）。
  • 別々の CPU コアに置いた 3 本のスレッドが、同じ予定を競って送ります。その時刻に動けたスレッドが送ります。Android ではアプリが自分のスレッドを最優先にできず、優先度の高い処理がコアを使うと、ふつうのスレッドは数 ms 止められることがあります。別々のコアで競わせることで、それがまれになりました（試したタブレットで平均の遅れ 0.01〜0.03ms）。
  • 書き込む順番は守るので、ノートオフが次のノートオンを追い越すことはありません。

線の上ではクロックを優先する

  • MIDI 端子（5 ピン）は 1 バイトに約 0.32ms、ノートや CC 1 つで約 1ms かかります。拍の直前にノートオフがまとまると、次のクロックが数 ms 待たされることがありました。
  • DBR-1 は線が空く時刻を数えていて、ノートや CC が次のクロックまでに流れ終わらないなら、そのクロックの直後に回します。クロック・Start・Stop を先に送ります。オートメーションの CC は、1 つのパラメーターにつき約 12ms おきに間引きます。

3. 測った結果

測り方: タブレット（Lenovo Tab K11、Android 15）を USB の MIDI モードで Windows の PC につなぎ、PC の小さなプログラムでクロック 1 つ 1 つが届いた時刻を記録しました。それを「まったく揺れないテンポの直線」と比べています。基準として、専用のグルーヴボックスも同じ方法で測りました。USB は MIDI を 1ms ごとに運ぶので、この方法では約 0.3ms より細かい差は見えません。

アプリの中では

エンジンだけを動かすテストでは、84〜174 BPM・スウィングあり・半端なパターンの長さ・音声の処理の呼ばれ方の揺れありの条件で、クロックの時刻の誤差は最大 1 サンプル、平均のテンポのずれは 0.0006 BPM 以内でした。タブレットの上で、クロックを Android に渡し終わるまで 1ms を超えたのは約 0.3% です。PC で見えたそれ以外の遅れは、渡した後で起きています。

効かなかったこと

  • 時刻を付けて Android に送ってもらう（前の送り方の TIMING: SYSTEM）。Android はミリ秒単位で待つので、クロックごとに 0〜1ms、ばらばらに遅れました。今の送り方は、いつも時刻ちょうどに自分で送ります。
  • クロックの直前に 1 バイト送って Android の MIDI の処理を起こしておく。中央値が悪くなったので、やめました。
  • オーディオインターフェースで Android の MIDI の処理を通らずに送る。USB の機器へ直接送るのは MIDI だけの機器ならうまくいきます（USB DIRECT）が、音声も扱う機器では音の出力が途切れました。今は MIDI だけの機器にだけ使います。

4. DBR-1 をマスターにするとき

つなぎ方（安定する順）

  1. MIDI だけの USB の機器 + USB DIRECT を ON: MIDI インターフェースや、MIDI OUT 端子のあるキーボード・コントローラー（その端子から機材へ）。Android の MIDI の処理を通りません。ON の間、その機器からの MIDI IN は使えません。OFF にした後は機器を挿し直してください。
  2. ふつうの送り方: オーディオインターフェースの MIDI OUT、USB で音声も送れるシンセ、PC など。正確さは 3 章のとおりです。音声も扱う機器は自動で見分けて、いつもこちらになります。
  3. Bluetooth の MIDI は遅れと揺れが大きく、クロックには向きません（DBR-1 は Bluetooth MIDI に対応していません）。
    • USB で音声も送れるシンセは、USB の設定を「MIDI だけ」にしないと、音声の機器として扱われます。Android が DBR-1 の音の出力先をそのシンセに切り替えることもあります。
    • 出口（ポート）が複数ある機器は、OUT PORT で裏の MIDI OUT 端子につながる出口を選びます（多くは 2 番目）。機器の側で、USB から来た MIDI を MIDI OUT へ流す設定が要ることもあります。

    MIDI… の設定

    • SENDER: NEW（既定）。OLD は NEW で困ったときだけ。
    • CLOCK: SEND でクロックと Start / Stop を送ります。STOP の後に続きから再生すると、位置（Song Position Pointer）と Continue を送ります。
    • PROGRAM: OUT を ON にすると、パターンが変わったときにプログラムチェンジ（番号 = パターン番号）を、新しいパターンの最初のノートより先に送ります。プログラムチェンジでパターンを切り替える機材なら、小節の頭で一緒に切り替わります。
    • OFFSET は、送るもの全体を早く・遅くします。揺れは変わりません。

    MIDI 端子を混ませない

    クロックが待たされることはありませんが、5 ピンの端子が混んでいると、ノートや CC は数 ms 遅れて届くことがあります。複数のチャンネルへの和音、速いテンポで MIDI を割り当てたパッドがたくさん、たくさんの CC の動き、が重なると混みます。外の機材が使わないチャンネルは機材の側で無視する設定にするか、MIDI… の NOTES / CC のチェックを外してください。

    端末のこと

    • 再生中、送信は CPU の 1 コアの 2 割弱を使います。時刻ちょうどに送るため、直前は眠らずに待っています。
    • 端末が熱いときや省電力モードでは、ときどきの遅れが増えることがあります。
    • 音の出力先が変わる（USB の音声の機器を抜き挿しする）と、時刻の基準を取り直すので、その瞬間はテンポがよれます。再生中は避けてください。
    揺れが気になるときは、別に親（MIDI クロックの専用機・DAW・リズムマシンなど）を用意して、DBR-1（CLOCK: RECEIVE）とほかの機材をその親で動かすのがおすすめです。DBR-1 は自分の時計で刻みながら受けたクロックになめらかに合わせるので、クロックの小さな揺れでリズムが揺れません。なお、DBR-1 自身の音は音声エンジンが時刻を決めているので、どの場合も MIDI クロックの揺れの影響を受けません。

    5. わかっている限界

    • 測定はほとんど 1 台のタブレット（Lenovo Tab K11）で行いました。CPU のコアやスケジューラが違う端末では、数字が変わることがあります。
    • USB DIRECT の道と、5 ピンの MIDI ケーブルの上の信号は、PC の方法では測れません。私たちの環境では USB DIRECT のほうが安定して感じられましたが、数字はありません。
    • タブレットを USB の MIDI 機器として PC につないだとき（「Android USB周辺機器ポート」）は、Stop が PC に届きません。オーディオインターフェース・MIDI の機器・USB DIRECT では、Stop と Continue が届きます。
